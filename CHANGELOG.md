# Changelog

## Unreleased

`investigate` plans or runs the passive adapters for one domain, email, username, or IP. `--resume --id` retries sources that did not complete and diffs that attempt against the previous snapshot. Absence in the diff is not removal. Active probes stay off. `sources` lists every adapter, whether it is enabled, and which required or optional API key names are missing. Key values are not printed. Completed collections still use the workspace TTL cache. HTTP 429 and 5xx still retry with backoff and Retry-After. Historical certificate and archive cursors are not served from that cache.

Candidate links connect an email to its domain, a mailbox local part to a username, and a username to a public GitHub or Keybase profile. Each link has a confidence score and a sentence that explains the rule. A shared handle stays a candidate. The offline HTML report adds an executive summary, an observation timeline, and that candidate graph. The page does not load a script, font, or data from a CDN. `report --format csv` uses the same finding columns as the JSON report. STIX export still uses the stored in-scope entities and does not promote candidate links.

`ocr-image --save` and MCP `ocr_image` with `save: true` store the extracted text when the document basename is listed in `scope.documents`. Other documents are not written. The text stays untrusted. SQLite schema v8 adds `investigations` without rewriting evidence. Package version remains 0.4.0.

Findings queries escape `%` and `_` in SQL `LIKE` patterns, so a target that contains an underscore no longer matches a different character.

crt.sh certificate values that contain whitespace, including `AS207960 Test Intermediate - example.com`, are classified as non-DNS names. The bundled `examples/crtsh.json` import completes with status `ok`. Maigret imports keep every claimed HTTPS profile for a scoped username, with site name, URL and status. Holehe CSV and Social Analyzer JSON imports store found accounts as findings and rate-limited, unknown or failed checks as coverage gaps. The people workflow alias lookup budget is `--max-targets` / MCP `maxTargets` (1–10, default 3). Node older than 24.14 prints `NODE_VERSION` instead of crashing on `node:sqlite`. `NETWORK_DISABLED` and `HIBP_KEY_MISSING` hints name the configuration flag and `HIBP_API_KEY`. Image commands that do not open the database suppress only the SQLite experimental warning.

Added passive adapters for domain RDAP, DNS-over-HTTPS, AlienVault OTX, HackerTarget, urlscan.io, Shodan InternetDB, SecurityTrails, VirusTotal, GitHub public keys, GitHub public-event emails, Gravatar, Keybase and EmailRep. `pipeline` and `passive` run every enabled passive adapter for the target, deduplicate entities, tag each observation with its source, and record failures, rate limits and missing keys as coverage gaps. Required environment variables are `SECURITYTRAILS_API_KEY` and `VIRUSTOTAL_API_KEY`. Optional variables are `URLSCAN_API_KEY`, `EMAILREP_API_KEY`, `OTX_API_KEY` and `GITHUB_TOKEN`.

ProjectDiscovery httpx probing of discovered hosts is opt-in. `probe-http` and the company workflow require both `--probe-http` and `--authorized`, plus active mode. The batch probe checks that the binary is ProjectDiscovery httpx, uses one thread, the configured rate and timeout, and does not crawl or brute-force. JSONL import stores URL, status, title, technology, web server, TLS, IP and CDN. MCP tool `probe_http` uses the same flags. Package version remains 0.4.0.

Added `privacy-check-image` and MCP `privacy_check_image` for an offline check of your own photo before publishing. The report includes exact GPS coordinates and altitude, camera make and model, serial numbers, owner and copyright tags, software, and timestamps. GPS is rated high, serial and owner tags medium, and dates, software, and make/model low. The command does not write the workspace database. `analyze-image` still omits coordinates. `--scrub --output PATH` writes a metadata-stripped copy, rechecks it, and exits non-zero if GPS or identifying tags remain. The original file is not modified. JPEG, PNG, and WebP use a built-in stripper. `exiftool` and `mat2` are optional backends when `doctor` finds them on PATH. Package version remains 0.4.0.

Added a read-only investigation graph and expanded the synthetic benchmark from 36 to 52 cases. `graph --case UUID` or `graph --investigation NAME` with `--format json|html` writes entities, evidence, hypotheses and decisions. Candidate links stay candidates. The HTML file is offline, has no CDN or network requests, and escapes stored text. The MCP tool is `investigation_graph`. The benchmark reports per-category precision and recall, false attributions, a scope-block rate, export reproducibility and a secret-leak count. Package version remains 0.4.0. Schema remains v7. Existing MCP tool names, output schemas and the paginated `graph` command are unchanged.

Added investigation hypotheses and local cases. `hypothesis create|update|close|list|evaluate` and `case create|list|summary|report|export-stix`, plus the MCP tools `create_hypothesis`, `update_hypothesis`, `close_hypothesis`, `list_hypotheses`, `evaluate_hypothesis`, `create_case`, `list_cases`, `case_summary`, `case_report` and `export_case_stix`, store hypotheses and group them with investigations, targets, review decisions and notes. `evaluate_hypothesis` reads stored rows and the evidence-intelligence assessment. It returns supporting, contradicting and missing evidence and may set `open`, `supported-pending-review` or `weakened`. It never sets `analyst-confirmed`. That status is stored only by an explicit analyst close, and it is still not a finding. Contradicting evidence weakens a hypothesis. A suggested step that needs network, active mode, or an adapter is labeled with `requires_gate` and is not executed. Out-of-scope entities cannot be attached. The case report separates confirmed analyst decisions, candidates, hypotheses and limitations. Case STIX export calls the existing exporter and records each hypothesis as a note, not an indicator. SQLite schema v7 adds `hypotheses`, `cases` and `case_members` without rewriting existing rows and rejects a newer database. The synthetic benchmark reports hypothesis support precision, recall, false confirmations, weakened matches and adversarial passes. Package version remains 0.4.0. Existing MCP tool names and output schemas are unchanged.

Added a read-only evidence intelligence assessment. `assess` and the MCP tools `assess_evidence` and `explain_asset` score each in-scope domain, IP, ASN, URL and technology separately for historical existence, current activity, organization attribution, historical-versus-recent conflicts, source independence and the stored analyst decision. A suggested next action stays inside the current scope, network, active-mode and adapter gates and does not collect or record a decision. Duplicate, mirrored, same-upstream and same-run sources count once. A shared IP, CDN or hosting/registry ASN is not ownership. A shared name or handle stays a candidate. Historical certificates and archives are not current activity. The labeled benchmark reports attribution precision, recall and false-attribution counts against the v0.4 `explain_entity` heuristic. Package version remains 0.4.0. Schema remains v6. Existing MCP tool names and output schemas are unchanged.

Added a read-only STIX 2.1 export. `export-stix` and `export_stix` turn stored, in-scope evidence into a bundle with deterministic UUIDv5 identifiers. Suspected lookalikes stay suspected indicators, analyst decisions become notes and opinions, and out-of-scope rows are omitted. `validate-stix` checks the bundle offline. An operational runbook and a release checklist are documented in [PRODUCTION.md](docs/PRODUCTION.md). The checklist does not bump the version, tag, or publish a GitHub release. Package version remains 0.4.0. Schema remains v6. Existing MCP tool names and output schemas are unchanged.

Added local incremental monitors. `monitor add|run|diff|list` and the MCP tools `create_monitor`, `run_monitor`, `monitor_changes` and `list_monitors` store a definition, snapshot a run, and diff subdomains, hosts, certificates, DNS records, phishing lookalikes and exposures. Significance rules record an explicit basis. Alerts stay local unless an optional webhook is configured, and that hook is skipped while network access is disabled. There is no scheduler. New entities remain unreviewed. SQLite schema v6 adds the monitor tables without rewriting existing rows and rejects a newer database. Package version remains 0.4.0. Existing MCP tool names and output schemas are unchanged.

Added persistent analyst review decisions (`accept`, `reject`, `needs-more-evidence`) with append-only history, candidate entity links, contradiction flags and independent-source corroboration counts. A shared name or handle never confirms an identity. SQLite schema v5 adds the review tables without rewriting existing evidence. Three MCP tools and CLI commands expose the queue, decisions and entity view. Package version remains 0.4.0. Existing MCP tool names and output schemas are unchanged.

Added a scope-gated phishing lead workflow. It generates deterministic lookalikes of one in-scope apex and can enrich only those names from configured crt.sh, Cert Spotter, domain RDAP, Wayback and active-gated DNS. Candidates stay `suspected`, enter the review queue, and are reported as unverified leads. `phishing-scan`, `phishing-report`, `run_phishing_workflow` and `phishing_report` are additive. Package version remains 0.4.0.

## 0.4.0 — 2026-11-07

Added bounded Cert Spotter and Wayback CDX connectors/imports, atomic persistent continuation, historical hostname/URL relationships and explicit restart. Added deterministic evidence packages, paginated MCP export and offline integrity verification. Every MCP tool now has a validated output schema; the server exposes 20 tools. Partial/deferred collection is separated from execution failure, which changes v0.3 MCP response semantics. Added 17 labeled benchmark scenarios and CI gates, freshness/conflict assessments and planner source-yield/request-cost samples. SQLite schema v4 preserves existing evidence and jobs; original captures are not backfilled with missing provenance.

See [v0.4 operations and migration](docs/V0.4.md).

## 0.3.0 — 2026-11-07

Added durable jobs and checkpoints, lease recovery, cancellation, sealed snapshots, coverage-aware run comparisons, shared provider budgets/cooldowns, local doctor probes, provenance explanations, ranked planning and offline interactive HTML reports. Added ten MCP tools and checksum-pinned native integration labs. Correlation totals now remain separate from samples. Existing evidence is preserved by schema migration; pre-v0.3 historical snapshots cannot be reconstructed.

## 0.2.0 — 2026-11-07

Added seven CLI/MCP workflows with budgets, candidate aliases, professional/public-office context, MX, RDAP, routing ASN data, public GitHub profiles and bounded Sherlock/theHarvester wrappers. Added WhatsMyName, TruffleHog and breach-summary import bridges. Documentation and user-facing workflow names are English; original workflow names remain compatibility aliases.

Secret values/prefixes are discarded. MX, username matches and breaches are not treated as mailbox, identity or credential verification.

## 0.1.0 — 2026-11-07

Initial JSON CLI, MCP server, normalized SQLite evidence, provenance, deduplication, graph, cache, limits, adapters/importers, offline demo and CI. Added project documentation and the supplied banner; preserved Jenmar Rondon's MIT license.
