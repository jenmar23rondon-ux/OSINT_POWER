# Investigation quality benchmark

Run `npm run benchmark` or `node benchmarks/runner.js --output benchmark.json`. The optional output path must not exist. The benchmark uses real parsers, normalization, scope validation, SQLite ingestion, graph construction and mocked API collection. It makes no external requests or model calls.

`benchmarks/cases.json` contains 35 labeled scenarios with explicit expected entities and relationships, plus semantic checks for deterministic lookalike generation, monitor diffs and cross-source attribution. Cases cover deduplication, IDNs, exclusions/suffix confusion, overlapping CT sources, certificate wildcards, historical versus live URLs, shared IP infrastructure, username collisions, unknown accounts, mismatched profiles, public emails, breach-only associations, secret references, invalid calendar dates, stale evidence, conflicting public-company assertions, in-scope lookalikes, significance rules, duplicate and mirrored sources, CDN and hosting-ASN attribution traps, historical-only activity, and foreign-organization contradictions. The lookalike and monitor-diff cases do not add entity or relationship gold labels. The monitor case checks added, changed and coverage-gap keys, and it expects alerts only for a new brand-term certificate, a lookalike whose MX appeared, and a new exposed service.

The runner reports true/false positives and false negatives for entities and relationships, precision/recall against the fixture labels, semantic failures, mocked HTTP request counts and elapsed runtime. Per-source yield reports new entities in fixture order. For the 20 labeled assets in the evidence-intelligence cases it also reports attribution precision, recall and false-attribution count for two readers of the same stored rows: v0.4 `explain_entity`, which always leaves ownership `not_established`, and the evidence-intelligence assessment. A false attribution is a `verified` ownership status whose gold label is not verified. CI fails if a case introduces an unexpected finding/relationship, loses an expected one, verifies an unlabeled asset, or violates a labeled semantic check. Runtime is informational and has no platform-dependent threshold.

On this corpus the v0.4 reader has attribution precision 0 and recall 0, with 0 false attributions and 2 missed verified claims, because it never verifies ownership. The evidence-intelligence reader has attribution precision 1 and recall 1, with 0 false attributions, on those same 2 verified claims and 18 negative labels. That comparison is a regression control. It is not an estimate of real-world precision or recall.

The corpus expects 47 entity findings and 16 distinct relationships across its independent workspaces. A perfect score on this small synthetic corpus is not an estimate of real-world precision or recall. No statistical confidence calibration is claimed. Add reviewed, legally redistributable examples and independently maintained gold labels before using benchmark scores to make production accuracy claims.

To extend the corpus, add a case with descriptive tags, collection/import steps, explicit expected entity/relationship tuples and optional assessment expectations. Confirm that labels express the evidence available in the fixture. Keep historical assets, uncertain identity links and ownership assertions separate. Never add real passwords, tokens or personal investigation data.
