# v0.4: discovery, evidence and AI contracts

This release extends the existing resumable investigation engine. It does not require a model API or add a hosted service. The original MIT license and README banner remain unchanged.

## Historical discovery

Add `certspotter` and/or `wayback` to `enabledAdapters`. Enable `network`; these APIs do not require active mode. All targets pass the existing domain/exclusion checks. The company workflow includes one call to each enabled historical connector, within its existing call budget. The legacy passive pipeline retains its crt.sh/subfinder/Amass behavior.

```bash
node src/cli.js run --adapter certspotter --target example.com
node src/cli.js run --adapter wayback --target example.com
```

Each call fetches one page. Repeat it to continue. Cert Spotter uses the last issuance ID as `after`; Wayback uses the CDX resume key. State lives in the same SQLite database. Response-controlled continuation values become encoded parameters on fixed HTTPS endpoints, never new destinations. Optional `CERTSPOTTER_API_KEY` is read only from the environment and sent only in the API authorization header.

Cert Spotter's domain search returns unexpired issuances, not a complete history of every certificate. Empty polling retains the last issuance cursor and respects `Retry-After`, including successful HTTP responses. Wayback projects timestamp/original/statuscode/digest, limits requested rows to at most 1000 and accounts for hostname/URL output expansion. Once a Wayback traversal is exhausted, further calls return without another request until explicit restart:

```bash
node src/cli.js run --adapter wayback --target example.com --restart
```

MCP `collect` accepts `restart: true` for these two adapters only. Restart does not delete accumulated findings. It still obeys provider reservations/cooldowns. Each new job freezes its existing batch; restarting discovery does not reset completed checkpoints in an older job.

Continuation advances in the same SQLite transaction as evidence ingestion. Invalid/truncated pages retain their cursor; increase the record limit or resolve the provider format before retrying. Concurrent ordinary workers cannot rewind a cursor. Interrupted requests may repeat, with evidence deduplicated. Continuation state survives process restarts but is not a distributed cross-machine queue.

Both adapters preserve record context and mark coverage as `incremental_page`, with `coverage_complete: false`. Wayback keeps the archive date as observation time, strips URL queries/fragments and creates `historically_served` edges. It does not download archive content or confirm current service availability. Incremental snapshots can show additions and changed evidence; absence remains a coverage gap, even on the final page.

Imports accept the corresponding API JSON responses. Wayback imports require the four projected columns and accept the documented trailing empty row/resume-key row. Imports do not advance live collection cursors. Raw continuation values are kept in local state; public run summaries expose only cursor hashes and progress flags.

## Reproducible evidence packages

```bash
node src/cli.js bundle --id IMMUTABLE_RUN_OR_SNAPSHOT_UUID --output evidence.json
node src/cli.js verify-bundle --file evidence.json
```

The CLI creates a complete JSON package, refuses overwrite, and limits exports to 10000 observations/40 MB of capture data. Verification reads at most 50 MB and works without a workspace configuration or network access. Use MCP pagination for larger captures:

```json
{ "run_id": "IMMUTABLE_RUN_OR_SNAPSHOT_UUID", "limit": 25 }
```

Call `export_evidence`, then pass `page.next_cursor` as `cursor`. A page includes the complete capture count/digest, selected source summaries, payload/provenance and page-integrity digests. A partial page can be checked independently, but cannot establish the completeness of the entire capture. The standalone complete export verifies the ordered complete-capture digest as well.

Packages are deterministic for an immutable run and contain selected normalized evidence, not original HTTP bodies, full documents or raw secret values. They include input hashes, collector/parser/framework versions and configuration digests when recorded. Native collector versions are the last local doctor probe or `not_recorded`; imports report `external_version_unknown`. Older captures retain missing fields rather than inventing them. Configuration digests do not include environment credentials.

Integrity uses SHA-256 over canonical JSON. It detects inconsistent contents without authenticating the publisher. A party that edits a bundle and recomputes every digest can create a different internally consistent bundle. Keep a trusted manifest hash separately if authenticity matters. Automatic review decisions, encryption and signed attestations are future work.

## MCP migration

The server exposes the original 20 collection and evidence tools, plus `list_review_queue`, `record_decision`, `show_entity`, `run_phishing_workflow` and `phishing_report` (25 tools). Existing tool names and output schemas are unchanged. Each tool declares a distinct output schema with required result fields. The envelope adds:

| Field                     | Meaning                                                               |
| ------------------------- | --------------------------------------------------------------------- |
| `schema_version`          | `0.4`                                                                 |
| `execution_status` / `ok` | Whether the tool operation succeeded                                  |
| `collection_status`       | completed, partial, deferred, failed, cancelled or not_applicable     |
| `coverage.complete`       | Completeness for collection operations; null for non-collection tools |
| `coverage.truncated`      | Whether the returned result explicitly reports truncation             |
| `retry`                   | Whether retrying later may help, with the known minimum wait          |

Partial/deferred collection returns `ok: true` and omits MCP `isError`; consumers must inspect collection/coverage state. Input exceptions and failed collection return `ok: false` with `isError: true`. Cancellation/inspection commands can succeed even when the job is cancelled. The CLI retains its earlier JSON shape and nonzero exit status for partial/deferred/cancelled runs.

Validation failures in internal result construction return `INTERNAL_OUTPUT_VALIDATION`; malformed results are not passed through to an agent. `schema/mcp-output.schema.json` contains generated tool contracts. Collector evidence and intentionally extensible checkpoint/provider records retain bounded JSON fields; these are data, never instructions.

## Assessment and planning

`explain_entity` separates existence evidence, ownership, candidate identity and freshness. Its default assessment window is 30 days. Future-dated records are counted separately. Distinct public-company assertions are flagged for review without deciding whether they represent a contradiction, time change or wrong identity. Assessments are based on the returned evidence sample and disclose sampling. Its `review_status` remains the heuristic `unreviewed`. Persisted analyst decisions, candidate links and contradiction flags are a separate schema v5 layer and do not change this assessment.

## Evidence review

`review_decisions` stores append-only `accept`, `reject` and `needs-more-evidence` rows with a reason, analyst id and timestamp. `entity_links` stores the current candidate or confirmed link, its confidence and the observations behind it. Opening an older database creates those tables and preserves existing rows.

A shared name or handle never confirms an identity. The same handle on a GitHub profile and in an email local-part stays a candidate even when many sources repeat it and even after an analyst accepts the profile. Confirmation requires a non-name identifier, such as a full email address, profile URL or key fingerprint, supported by at least two independent sources. The same `upstream`, the same `mirror_of` origin, or the same collector run counts as one source. Contradictions are recomputed when sources disagree on an attribute of an entity or of a linked pair.

`plan_investigation` exposes up to 20 completed uncached source/target samples. It reports mean new/unique entities, observed HTTP requests and elapsed duration. At least three samples are required before novelty-per-request contributes a bounded ranking adjustment. Import order, source overlap and scope affect yield. Native internal requests are unknown. These metrics are not source-precision estimates or calibrated probabilities. Exhausted Wayback traversals are explicitly ineligible until restarted.

## Validation

`npm test` exercises real MCP sessions, cursor recovery/conflicts, malformed pages, provider waits, evidence integrity and existing workflow behavior. `npm run benchmark` runs the labeled synthetic corpus on Windows/Linux CI. The separate pinned Linux native lab remains in place. Live historical-provider requests are not CI dependencies; mocked contract coverage does not certify current provider availability, subscriptions or rate allowances.
